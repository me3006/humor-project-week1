# Fix the public collection in the existing Supabase project

The live category query returned HTTP 404 / `PGRST205`: `public.wt_generations` and `public.wt_stories` were not found in the schema cache. The category filter cannot load cards until the application tables exist and contain public entries. No fallback cards or made-up successful database reads have been substituted.

1. Open your **existing Supabase project → SQL Editor → New query**.
2. Copy the complete contents of `supabase/migrations/202610150001_journal.sql`, paste, and click **Run**. This creates the journal tables, functions, and RLS policies. It preserves existing profiles and legacy jokes. Run this base migration only if the journal tables are not installed (which is what the live diagnostic currently reports).
3. Create another query, paste all of `supabase/migrations/202610190001_roommate_life.sql`, and click **Run**. This adds Roommate Life to the allowed database categories and refreshes the API schema cache. It preserves existing stories, generations, and ratings. If you previously applied the base migration, apply just this new migration.
4. In `.env.local`, preserve the working public Supabase variables and add `SUPABASE_SERVICE_ROLE_KEY` (Supabase → Project Settings → API Keys → copy a secret key beginning `sb_secret_`; the older `service_role` key is also accepted) and `GEMINI_API_KEY` (your **Free tier** Google AI Studio project's key; follow [FREE-AI-SETUP.md](../FREE-AI-SETUP.md)). Do not paste secrets into chat or commit them. These same server-only variables are also needed in your existing Vercel project's environment settings. The environment variable keeps its existing project name even when you use a newer `sb_secret_` key. This key enables seeding but cannot itself apply SQL migrations.
5. Run `npm run seed`. It generates and saves matching AI jokes and their actual prompts for **24 fictional stories across eight categories**, including three Roommate Life stories. Existing seed keys are skipped, so rerunning does not duplicate content. If all older categories are already seeded, you may use `npm run seed -- --category=roommate-life` to add only the new category. AI failures stop the command rather than saving fabricated results.
6. Run `npm run diagnose:database`. It needs only the public credentials and runs the same category-specific query as the website for all eight categories. Every category must report **PASS**, with at least three matching public stories and jokes.
7. Run `npm run test:integration` for the additional service-role checks of seed prompt storage and private-data restrictions. Refresh `http://localhost:3000/categories/roommate-life`. Its cards should load; after signing in, Create and Rate use that same category.

If SQL Editor reports an error, keep the exact error text. Do not disable RLS or grant anonymous write access as a workaround. Read-only diagnostics distinguish missing tables/relationships, permission errors, network failures, and missing seeds.
